# 红利 MA30 停车策略 · 自动提醒系统

每个交易日北京时间 21:00 自动抓数、算信号、记账、推送到手机。非交易日静默。

面板：https://binbin1555.github.io/hongli-ma30/

---

## 这套系统在做什么

在中证红利指数上执行「跌了买一档、涨了卖一档」的分档波段，不在股票里的钱放债券基金。

| | |
|---|---|
| 信号源 | 中证红利**全收益**指数 H00922（不能用价格指数 000922） |
| 均线 | MA30 = 最近 30 个交易日收盘价的算术平均，含当日 |
| 买入 | 收盘 < MA30 × 0.97 → 档位 +1 |
| 卖出 | 收盘 > MA30 × 1.02 → 档位 −1 |
| 档位 | 0 / 1 / 2 / 3 / 4 份，对应仓位 0 / 25% / 50% / 75% / 100% |
| 一天最多 | 动一档 |
| 执行 | T 日收盘出信号 → T+1 日收盘成交 |
| 下单金额 | 目标市值法：买 X =（w×S − V）/（1 + w×c），卖 X =（V − w×S）/（1 − w×c） |
| 实际买卖 | 红利ETF 515180（易方达，跟踪中证红利 000922） |
| 下单以哪个数为准 | **面板计算器**（填你券商 App 的真实数字）。推送和横幅里的金额是按本金推算的**估算值** |
| 闲钱 | 债券基金，业绩基准中证全债 H11001 |

买卖阈值刻意不对称（买 −3%、卖 +2%）。一轮完整来回的毛利空间是 1.02÷0.97 = **+5.15%**，这是策略对抗均线下行的全部缓冲垫。**不要对称化。**

## 架构

```
cron-job.org ──每交易日 21:00 HTTP──> Cloudflare Worker（唯一会跑代码的组件）
                                          │
                                          ├─ 深交所日历：今天开市吗？不开市就静默退出
                                          ├─ 中证接口：抓 H00922 + H11001
                                          ├─ ETF 行情：腾讯→新浪→东财三源依次尝试（换算股数）
                                          ├─ 10 项校验，任何一项不过就告警且不写入
                                          ├─ 算 MA30 / 信号 / 档位
                                          ├─ git commit 到本仓库 ← 这就是不可更改的账本
                                          └─ Bark 推送到手机

手机 ──> GitHub Pages（纯静态页面）──读──> 仓库里的 data/*.json
```

**手机永远不需要访问 Cloudflare。** 前端是纯静态的，直接读仓库里的 JSON，所以国内访问只依赖 GitHub Pages。

**仓库里没有任何金额。** 账本只记日期、指数收盘价、档位从几变到几。金额由本金实时推导出来——因为金额本来就是「档位 + 总资产」的确定函数。所以这个仓库可以公开而不泄露你的资金规模。本金存在两个地方：Worker 的密钥（用于生成推送文案）和你手机浏览器的 localStorage（用于显示面板）。两边用的是同一份 `shared/strategy.js`，算出来必然一致。

**账本为什么改不了。** 每天一次 git commit，git 是内容寻址的：改动任何一条历史记录都会让它之后所有 commit 的哈希全部变化，在 GitHub 上一眼可见。这比在代码里写个「已锁定」标志可靠得多。

## 部署

### 1. 发布仓库

已完成：https://github.com/binbin1555/hongli-ma30 （公开，默认分支 `master`）

### 2. 打开 GitHub Pages

仓库 Settings → Pages → Source 选 `Deploy from a branch`，Branch 选 **`master`**（本仓库的默认分支）、目录选 `/ (root)` → Save。
一两分钟后 https://binbin1555.github.io/hongli-ma30/ 就能打开。

### 3. 建一个 GitHub Token

GitHub Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token：

- Repository access：只选 `binbin1555/hongli-ma30` 这一个仓库
- Permissions → Repository permissions → **Contents: Read and write**（其他都不要给）
- 有效期建议选 1 年，到期前 GitHub 会发邮件提醒

### 4. 部署 Worker

Cloudflare Dashboard → Workers & Pages → Create → Connect to Git → 选这个仓库。
构建配置留空即可（wrangler.toml 已经写好）。

然后设置 4 个机密（Settings → Variables and Secrets → Add，类型选 **Secret**）：

| 名称 | 值 |
|---|---|
| `GITHUB_TOKEN` | 上一步生成的 token |
| `BARK_KEY` | Bark App 里那串设备 key |
| `RUN_TOKEN` | 自己编一串长口令，用来保护 /run 端点 |
| `PRINCIPAL` | 本金，例如 `1000000` |

Worker 会自动向 GitHub 查询默认分支，`main` 还是 `master` 都不用管。

**这四个值不要写进仓库里的任何文件。**

### 5. 配 cron-job.org

建**三个**任务：

| 任务 | URL | 频率 |
|---|---|---|
| 每日运行 | `https://<你的worker地址>/run?token=<RUN_TOKEN>` | 每天 21:00（时区选 Asia/Shanghai） |
| 盘中提醒 | `https://<你的worker地址>/remind?token=<RUN_TOKEN>` | 每天 14:30 |
| 每月刷新日历 | `https://<你的worker地址>/calendar/refresh?token=<RUN_TOKEN>` | 每月 1 日 03:00 |

**盘中提醒**只读不写：只在「今天正好是某笔挂单的执行日」时推一条，其余情况静默。
它防的是 T 日晚上看到通知、T+1 日却忘了下单——漏做超过一天，账本会继续往前走，
实盘就落后了。

每日任务设成周一到周五就够了 —— 周末交易所日历本来就返回非交易日，Worker 会静默退出。遇到调休上班的周六，日历会正确标记为交易日，所以**建议还是设成每天跑**，让日历去判断，而不是让 cron 去判断。

### 6. 首次验证

浏览器打开 `https://<你的worker地址>/health`，应该返回当前状态。
然后手动跑一次 `https://<你的worker地址>/run?token=<RUN_TOKEN>&force=1`，检查：手机收到推送、仓库多了一个 commit、面板数字更新。

## 10 项校验

任何一项 `fatal` 失败都会**阻止写入**并推一条带原因的告警。绝不静默失败。

| # | 检查 | 防的是什么 |
|---|---|---|
| 1 | 深交所日历确认今天开市 | 节假日、调休误推送 |
| 2 | 中证今日数据已到位 | 日历说开市但数据没出，宁可告警也不用旧数据算 |
| 3 | 日期严格递增，且每一天都在官方交易日历里 | 接口塞进不存在的交易日 |
| 4 | 幽灵行已清除 | 接口在区间起点补一行等于次日收盘价的假数据 |
| 5 | 涨跌幅与收盘价逐行对账 | 数据串行、错位 |
| 6 | 单日波动在 ±11% 内 | 明显的脏数据 |
| 7 | MA30 有满 30 个交易日 | 用不足 30 天的均线算出错误信号 |
| 8 | ETF 报价日期与指数日期一致 | 行情源会返回当日**盘中实时**价，用它换算股数会错 |
| 9 | state 档位与账本一致 | 提交只写了一半、或有人手改 state.json 导致状态与账本脱节 |
| 10 | 账本自审：日期与档位链完整 | **最重要的一项**：账本里只要有一天不在行情序列里，重放会静默跳过，后面每一笔金额都错但界面看不出异常 |

第 8 项非致命 —— 失败时只是不给参考股数，仍然给金额。

## 回归测试

```bash
npm test            # 回归测试（含文案测试）
npm run wording     # 只跑文案：打印每种状态的真实句子
npm run sweep       # 状态空间穷举（2808 组）
npm run check:sources   # 三个外部数据源体检
```

`npm test` 把 `shared/strategy.js` 的重放结果和独立的 Python 回测引擎逐笔对账
（三段历史、最多 62 笔交易路径，误差 < 0.01 元），另外覆盖：信号阈值边界、档位推进、
目标市值法公式、MA30 边界、北京日期换算、交易日推算、计算器方向不变量、补齐落点、
提示边界、校验体系逐项故障注入、状态文件校验、前端模块版本戳。

`npm run sweep` 穷举 5 档位 × 8 价格位置 × 3 挂单形态 × 3 资产规模 × 9 持仓占比，
检查「0 档不提卖出、满档不提买入、成交后精确落在目标仓位」等九项不变量。

`npm run wording` 跑的是 `index.html` 里的真代码 —— 把 `<script type="module">`
整段抠出来配 DOM 假件后 import 进来，穷举 15 种状态，打印「下一次操作」卡片、
触发横幅、Bark 推送的**真实文案**，并断言：不出现 `undefined`/`NaN`，
卡片和横幅不说两个时点、不说两个方向，「N 笔」和账本对得上，
以及推送里的「明日」当且仅当执行日真是第二天时才出现（2026 年 241 个信号日逐个验，
其中 50 个的执行日因周末和节假日不是第二天）。**改了任何提示文案都要跑一遍并读输出。**

`npm run check:sources` 值得偶尔手动跑 —— 两轮审查里最有价值的发现，
就是数据源会悄悄失效而系统只在日志里留一行。

**改动 `shared/strategy.js` 之后一定要跑前两个。**

## 需要留意的事

**这不是一个能长期跑赢中证红利指数的策略。** 拉到 20 年它大概率跑输，而且会输很多。它的定位是「停车位」：在等待大熊市底部期间保住本金、少亏钱。

**近十年的漂亮成绩里，约 89% 来自债券腿而不是择时。** 十年期国债收益率已经从 3.9% 降到 1.68%，这条腿的贡献不可能再复制。2025 年中证全债滚动一年收益一度是 −0.04%。

**它真正怕的不是「跌得深」，是「跌得慢、跌得久、中间不给反弹」。** 历史上唯一让这套规则彻底失败的是 2008 年那种长期阴跌。判断标准不看跌幅，看有没有出现 5% 以上的像样反弹。

**决定成败的头号变量是持有期内指数的最大回撤。** 回撤小于 25% 时基本必成，超过 50% 时基本必败。

**漏做了怎么办。** 系统按规则记账，不管你实际有没有下单（这是设计如此）。如果你漏做了几天，
实盘就会落后账本。面板的计算器会检测到并直接给出「一次补齐到账本 N/5 档」的金额——
注意它旁边「只走一档」的数字在落后两档时只有实际需要量的一半，别拿错。

**账本是理论口径。** 股票腿用全收益指数、闲钱用全债指数推算，不追踪你实盘的零头差异。实盘会有 ETF 跟踪误差、分红税负、冲击成本，**实际表现通常低于面板显示的理论值**。
面板上「每份该是多少钱」是个**独立的计算器**：填入你券商 App 里的真实「可用资金」和「已持有红利」，它会按这两个数字反推你在第几档、下一步该动多少钱。在那里填什么都不会影响操作提醒和交易记录——账户盈亏和账本金额只由**本金**推导。

**状态文件损坏时页面会整页停止渲染**，而不是显示一个看似正常的错数字。
Worker 读到损坏状态也会直接告警退出，不基于它算信号。

**退出规则尚未定义。** 这套策略是为了等一个大熊市底部、然后全部换成创业板 ETF 而存在的。换仓的触发规则目前还没定，而这个决定对最终结果的影响比这里所有参数加起来都大。

## 日常维护

**Worker 会自己往仓库提交。** 每个交易日 21:00 它会写 `data/`、`calendar/`、`audit/`，所以远端经常比你本地新。GitHub Desktop 弹「Newer commits on remote」是正常的，不是故障。

改代码的固定动作：

```
Fetch  →  Pull origin  →  改代码  →  Commit  →  Push origin
```

**不要在本地手动改这三个目录**，它们属于 Worker，改了才会真冲突：

| 目录 | 归谁 |
|---|---|
| `data/` `calendar/` `audit/` | Worker 写，只读 |
| `index.html` `worker/` `shared/` `tests/` | 你改 |

改完 `shared/strategy.js` 要跑两条命令：

```bash
npm run stamp   # 更新前端模块的版本指纹，否则浏览器会用缓存的旧模块导致白屏
npm test        # 和独立的 Python 回测引擎逐笔对账 + 全部单元测试
```

忘了 stamp 的话 `npm test` 会直接报错提醒你。
